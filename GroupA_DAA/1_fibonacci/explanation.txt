ASSIGNMENT 1 — FIBONACCI NUMBERS (RECURSIVE & NON-RECURSIVE)
============================================================

Problem Statement
-----------------

Write a non-recursive and recursive program to calculate Fibonacci numbers and analyze their time and space complexity.

Explanation
-----------

The Fibonacci sequence is defined as:
F(0) = 0
F(1) = 1
F(n) = F(n-1) + F(n-2)   for n > 1

Recursive approach (fib_recursive)
Directly translates the mathematical definition into code — the function calls itself twice for every n > 1. This creates a binary tree of calls. Many sub-problems (e.g. F(2)) get recomputed again and again because there is no memory of previously computed values.

Iterative approach (fib_iterative)
Keeps only the last two computed values (a, b) and walks forward from F(0), F(1) up to F(n) in a single loop, updating the two variables each step. No repeated work, no recursion.

Complexity
----------

Approach   Time    Space
---------  ------  ----------------------------------------
Recursive  O(2^n)  O(n) — depth of the recursion call stack
Iterative  O(n)    O(1) — only two variables are kept

Why O(2^n) for recursion: each call spawns 2 more calls (until the base case), so the number of calls roughly doubles with every increase in n — a full binary tree of height n.

Viva Questions & Answers
------------------------

Q1. Why is the recursive Fibonacci exponential while the loop-based one is linear?
Recursion recomputes the same sub-problems repeatedly (no results are stored), so the call count grows exponentially. The iterative version computes each Fibonacci number exactly once.

Q2. How would you make the recursive version faster without switching to iteration?
Add memoization — store already-computed F(n) values in a dictionary/array and return the cached value instead of recomputing. This brings recursive time down to O(n) at the cost of O(n) extra space for the cache.

Q3. What is the space complexity of the recursive version and why?
O(n), because each unfinished call stays on the call stack until its two recursive calls return — the maximum stack depth equals n.

Q4. What is the base case here and why is it needed?
n <= 1 returns n directly (F(0)=0, F(1)=1). Without a base case the recursion would never terminate.

Q5. Can Fibonacci be computed in O(log n) time?
Yes, using matrix exponentiation (raising the matrix [[1,1],[1,0]] to the power n) or a fast-doubling identity — both reduce the problem via repeated squaring.

Q6. What happens to the recursive version for large n, say n = 40?
It becomes very slow (millions of redundant calls) because of the O(2^n) blow-up, while the iterative version stays instant since it's O(n).

Q7. Is this problem better suited to Dynamic Programming than plain recursion?
Yes — Fibonacci has overlapping sub-problems and optimal substructure, the two properties that justify using DP. Memoized recursion or the bottom-up iterative version are both DP approaches.

Q8. Why do we call this a "non-recursive" approach instead of just "iterative"?
It's the standard term used to contrast with recursion — any approach that does not call itself (loops, matrix exponentiation, etc.) counts as non-recursive.
